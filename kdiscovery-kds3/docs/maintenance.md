# 维护、发布与敏感信息

1. 在独立虚拟环境安装 `.[dev]`，运行离线 pytest、`kdiscovery doctor`。
2. `python -m build` 生成 sdist 与 wheel；在另一环境安装 wheel 后运行 CLI 与假模型流水线。
3. 修改挖掘语义时添加通用回归案例并更新规则版本；不要把特定仓库名称写进调度规则。
4. 更新版本、CHANGELOG，并明确是否使旧断点失效。不要修改已有实验结果来适配新代码。
5. 上传只包含源码、格式、文档、测试和依赖声明；不上传 `.env`、`configure.json`、源码缓存、模型输入输出、实验或用户知识。

本模块不复制主应用配置。CLI 读取环境变量，Token 不写入输出文件或 Git。不要在远程地址中嵌入凭据。共享报告前另行检查源码和模型内容的访问权限。

本仓库内 `tests/excluded-host-tests.json` 记录未移植的主应用与旧 Joern 集成测试，不能用这些测试的历史通过数作为独立包验收结果。
